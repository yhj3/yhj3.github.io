Projects

  • Brain Tumor Segmentation on Multi-Modal MRI: U-Net vs. TransUNet
    Yihang Jiao. Independent project, 2025. This is where I first learned to handle biomedical data. I built one pipeline in which a U-Net, a configurable U-Net, and a TransUNet train under identical data and training settings, so that a change in the score can be traced to a single deliberate change. I expected a larger model to perform better. Making the U-Net deeper hurt performance, while fixing only the loss function improved it by roughly seven Dice points on an unchanged architecture. And even when the hybrid ResNet-ViT reached the best overall score, the improvement came almost entirely from one diffuse tumor subregion. This taught me not to trust a single averaged metric.
    Paper: yhj3.github.io/assets/papers/brats-unet-vs-transunet.pdf
    Write-up: yhj3.github.io/projects/brats.html
    Code available: https://github.com/yhj3/brats-unet-vs-transunet
    Weights available: https://huggingface.co/yihangj3/brats-transunet
  • VibeRepair+: Retrieval-Augmented Program Repair for Java and Python
    Yihang Jiao, Yingjia Gu, Shengyue Guo. CS Software Engineering for GenAI, 2026. My main contribution was the evaluation. At first we tested retrievers by asking them to find a bug inside the same 97k database they were built from, and every retriever received a perfect score of 1.000. I designed a simple check and found that this score was not meaningful: different retrievers agreed on only 34.1% of their top results. To fix this I built a pluggable retriever framework and a new external evaluation on 521 real, unseen bugs from Defects4J. Under the fair test a simple lexical method outperformed the dense embedding by 27.8%. This taught me that a benchmark can easily confirm itself if we do not question how it is built.
    Paper: yhj3.github.io/assets/papers/viberepair-plus.pdf
    Write-up: yhj3.github.io/projects/viberepair.html
    Code available: https://github.com/yhj3/Vibe_Repair_Plus
  • What LLM Rewriting Costs an Adversarial Attack
    Yihang Jiao. Research assistant, FOCAL Lab, with Prof. Gagandeep Singh, 2024; revised 2026. Standard attacks on text classifiers replace single words with synonyms. I tried having a language model rewrite whole sentences instead, and the rewrites read far more naturally. When I returned to this work a year later and ran the classifier on the rewrites, which the original evaluation had never done, only 44.5% of the attacks survived. The prompt that preserved them best turned out to work by instructing the model to change the topic, which produces a different input rather than an attack. This taught me my most important lesson, and I learned it from my own mistake: a number can look like evidence while measuring something else entirely.
    Paper (revised): yhj3.github.io/assets/papers/counterfactual-textattack-revised.pdf
    Paper (original 2024): yhj3.github.io/assets/papers/counterfactual-textattack.pdf
    Code available: https://github.com/yhj3/counterfactual-textattack
  • LLM RAG Reranker with Pairwise Comparison and Citation Context
    Yexin Wu, Yihang Jiao. CS 598 Text Mining, 2024. Search over papers ranks them by what they say about themselves, which is a poor guide to how useful a paper actually is. We reranked candidates by letting a language model compare them two at a time, and treated its noisy judgments as a bandit problem so that most comparisons could be skipped. We also collected the citation contexts of each paper, so that the reranker could see how a paper is used by others rather than only how it describes itself. This raised MRR from 0.485 to 0.572.
    Paper: yhj3.github.io/assets/papers/llm-rag-reranker.pdf
    Write-up: yhj3.github.io/projects/scilit-rag.html

What I want to work on next

Evaluation protocols for machine learning on scientific data. Leave-one-out and random splits are used to support many published results, and they overstate performance whenever the query and the answer come from the same source. In VibeRepair+ every retriever received a perfect score under a protocol that was really asking whether a document can find itself. The same shape appears wherever the split does not hold out the thing the model is supposed to generalize over. What I would like to build is a checkable recipe rather than a new model: a way to construct external queries, a two-stage leak check, and a random-retrieval floor reported next to every headline number. Biomedical data makes this sharper rather than softer, because labels are scarce, positives are rare, and batch structure often correlates with condition closely enough that a model can score well by reading the batch instead of the biology.

Also interested in: perturbational cell-state modeling. A protein's structure is mostly decided by its sequence, but a cell's state is decided by many things together, such as gene expression, protein abundance, and spatial organization. We almost never measure all of them in the same cell at the same time, so the modeling problem is also an information problem. I have not worked on this and have not thought it through in detail; I note it as an area I find interesting and would like to learn.
